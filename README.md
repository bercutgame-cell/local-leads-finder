# LeadScout — поиск потенциальных клиентов

Веб-приложение для поиска локальных компаний, которым может быть полезен сайт или лендинг.

**Текущая версия: 2.2 MVP**

## Что уже работает
- Нижняя фиксированная навигация с едиными SVG-иконками.
- Выбор бизнес-подкатегорий внутри основных категорий.
- Рабочая панель связи с клиентом в разделе базы: контакты, персональный редактируемый текст, копирование и переход к доступным каналам.

- Отдельные вкладки: поиск компаний, клиенты и предложения, шаблоны и сайты.
- Самостоятельный раздел загрузки HTML-шаблона.
- Последовательный переход между несколькими публичными зеркалами Overpass; одна поисковая попытка выполняется за раз, чтобы не создавать параллельную нагрузку.

- Тонкая линейная шкала прогресса поиска и время выполнения.
- Геокодер ограничен 12 секундами; каждый Overpass-сервер — 16 секундами, после чего выполняется переход к следующему.
- Библиотека HTML-шаблонов по категориям бизнеса и индивидуальная подстановка данных компании.
- Полноценное ручное редактирование всего HTML-кода отдельно для каждого клиента; сохранение HTML вместе с данными лида.
- Предпросмотр именно отредактированного HTML и скачивание готового `index.html` для передачи клиенту или публикации на статическом хостинге.
- Предпросмотр и скачивание полноценного HTML-файла на основе загруженного шаблона.
- Индикатор этапов поиска с ориентировочным процентом выполнения и прошедшим временем; процент не является точным серверным ETA.
- Редактор персонального лендинга для каждой компании: название, заголовок, телефон, email, адрес, описание, услуги и цены, текст кнопки.
- Сохранение настроек лендинга в карточке лида и выгрузка автономного HTML-черновика сайта.
- Поиск компаний по городу и категории в радиусе 3 / 5 / 10 / 20 км.
- Источник организаций — OpenStreetMap через Nominatim и Overpass API.
- Извлечение публичных сведений, если они внесены в OpenStreetMap: название, адрес, телефон, email, сайт, отдельные социальные ссылки.
- Отметка карточек, в которых в данных OpenStreetMap не указан сайт.
- Фильтрация результатов, сохранение лидов в локальную базу браузера, удаление и экспорт CSV.
- Подготовка текста первого обращения для ручной проверки и отправки.

## Запуск
Это статическое приложение. Открой `index.html` локально или включи GitHub Pages:
1. Repository → Settings → Pages.
2. Build and deployment → Deploy from a branch.
3. Branch: `main`, folder: `/ (root)`.
4. Save. GitHub покажет адрес опубликованного сайта.

Можно также развернуть репозиторий на Cloudflare Pages: подключить GitHub-репозиторий, выбрать корневую папку, build command оставить пустой.

## Важные ограничения MVP
- Отсутствие поля website в OpenStreetMap означает **«сайт не указан в источнике»**, а не доказанное отсутствие сайта. Перед предложением нужно проверить компанию вручную.
- Проверка качества существующего сайта пока не автоматизирована. В следующем этапе добавим проверку доступности, мобильной версии, HTTPS и базовых признаков качества.
- Покрытие зависит от полноты OpenStreetMap. Для более полного поиска можно подключить дополнительные лицензированные каталоги и API карт.
- Контакты из OpenStreetMap берутся только из открытых полей карты. Социальные страницы ищутся через подготовленные поисковые ссылки и проверяются вручную; автоматического сбора VK/Telegram/Instagram в текущей версии нет.

## VK, Telegram и MAX
В версии 2.0 автоматический сбор VK через Worker отключён: приложение не требует токенов, OAuth или серверной настройки. Ссылки на публичные страницы можно искать вручную через поисковые запросы и сохранять в карточке компании.
- Telegram: бот не может первым написать произвольному пользователю; для диалога нужен доступный публичный контакт или инициатива адресата.
- VK: интеграция отправки зависит от официального API, прав приложения и настроек получателя.
- MAX: подключение официального API/бизнес-инструментов требует отдельной проверки доступности и разрешений.
  
Следующий этап — контактные ссылки из публичных карточек, кнопки открытия найденных профилей и безопасные интеграции там, где это разрешено платформой.

## Публикация персональных сайтов
Версия 2.2 добавляет интерфейс публикации и серверный endpoint Cloudflare Worker. После подключения Worker кнопка «Опубликовать / обновить сайт» отправляет текущий HTML в защищённый endpoint, который записывает `clients/<slug>/index.html` в этот GitHub-репозиторий. При включённом GitHub Pages постоянная ссылка имеет вид `https://bercutgame-cell.github.io/local-leads-finder/clients/<slug>/`. Повторная публикация обновляет тот же файл и сохраняет URL.

### Однократная настройка сервера
1. В Cloudflare Dashboard открой Workers & Pages → Create → Worker. Назови его `leadscout-publisher`.
2. Открой Edit code и вставь полный код из `cloudflare/publish-worker.js`, затем Deploy.
3. В Settings → Variables and Secrets добавь два секрета:
   - `GITHUB_TOKEN` — Fine-grained Personal Access Token с доступом только к `bercutgame-cell/local-leads-finder` и разрешением Contents: Read and write.
   - `PUBLISH_PASSWORD` — придумай длинный отдельный пароль (не используй пароль GitHub).
4. В LeadScout → Сайты укажи URL Worker и тот же `PUBLISH_PASSWORD`. Адрес можно сохранить; пароль действует только в текущей вкладке браузера.
5. Убедись, что GitHub Pages включён для ветки `main`, папка `/(root)`.

GitHub-токен никогда не помещается в браузер, HTML приложения или репозиторий. Worker принимает запросы только с GitHub Pages origin, проверяет пароль, ограничивает размер HTML и записывает только в каталог `clients/`. Не публикуй в шаблонах секреты, закрытые данные или личную информацию без согласия компании. После коммита GitHub Pages может потребоваться немного времени на обновление.

В HTML-шаблоне доступны плейсхолдеры: `{{company_name}}`, `{{title}}`, `{{phone}}`, `{{email}}`, `{{address}}`, `{{website}}`, `{{description}}`, `{{button_text}}`, `{{services_text}}`, `{{services_html}}`. Для автономного файла CSS/JS лучше встроить в HTML или использовать абсолютные URL; относительные файлы ресурсов нужно добавить в ту же папку сайта.

## План развития
1. Проверка домена и качества сайта (мобильность, скорость, HTTPS, доступность).
2. Дополнительные источники компаний с соблюдением их условий использования.
3. Карточка лида: заметки, приоритет, статусы «Новый / Проверен / Написал / Ответил / Клиент».
4. Ручной запуск контакта через VK / Telegram / MAX, если публичная ссылка доступна.
5. Настраиваемые шаблоны сообщений и история взаимодействия.

## Конфиденциальность и ответственное использование
Храни базу в своём браузере и не отправляй массовые нежелательные сообщения. Используй только публичные деловые контакты, учитывай правила сервисов и применимое законодательство о персональных данных и рекламе.
